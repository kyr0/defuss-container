# Security boundaries

- API binds 127.0.0.1 only. 256-bit bearer token rotated on every daemon start; constant-time comparison; unexpected Host/browser Origin rejected; no permissive CORS. The UI calls through native Rust; no token in localStorage or frontend source.
- Desktop navigation is restricted to its initial local asset origin. The native bridge verifies the invoking window's origin and restricts API methods/path shape. It does not execute commands or access arbitrary files on JavaScript's behalf.
- Git URL credentials/query fragments, file/SSH schemes, ref option injection, path traversal, invalid application names, reserved environment keys and invalid port/resource specs are rejected. Processes are started with argv arrays, not interpolated shell commands.
- Build code executes inside a disposable microVM with private-address egress blocked. The only writable host share is its private output directory. Host artifact reads reject symlinks/hardlinks; other builder outputs are removed before host writes. Archive path/symlink/type/size checks defend the host packaging boundary.
- Application runtime guests have network and deliberate host access. `host` is an explicit capability, not a guarantee that arbitrary untrusted applications cannot reach sensitive host services. Bind/authenticate those services appropriately. The API token is never mounted inside a guest.
- The daemon runs with the user's privileges. Anyone who controls that account, daemon state directory, engine executable, or native UI code has equivalent authority. This is a single-user local tool, not a multi-tenant authorization system.
- Share directories must not overlap the daemon state directory and their path components must not be symlinks. Runtime input/etc are read-only; output is writable. Do not put host secrets into shared directories. Child symlinks inside user-selected shares are also subject to the engine's filesystem-sharing behavior.
- Repository `.env`/`.npmrc` are omitted, but arbitrary committed files can contain secrets. There is no automatic semantic secret scanner. App spec environment and logs are sensitive local data. Process output logs are bounded (approximately 8 MiB per job file; captured command tail 128 KiB). No total artifact retention quota in v0.1.
- Linux/macOS private directories use 0700 and atomically written credential files use 0600. The Windows installer restricts the state root to current user and SYSTEM. Run the installer before using the Windows daemon; custom pre-existing Windows directories need equivalent ACLs.
- Engine downloads have embedded release SHA-256 pins. Docker manifests/blobs are digest-verified and deployment artifacts are checksummed. Digest verification establishes integrity relative to the selected publisher; no supply-chain attestation claim.
- App code rollback does not roll back schema changes. Restore is performed stopped with a safety backup, but a crash mid-restore requires recovery from that backup. Never use `disk-durability=deferred` for authoritative data; this adapter explicitly chooses full.
- No OS prompt bypass. Distributing the GUI/daemon/helper requires ordinary signing, notarization, reputation and permissions appropriate to each OS.
